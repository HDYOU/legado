# 修复计划：精准管理 7 个子界面的 ActionBar 顶栏与精准管理对齐

> 范围：精准管理（`ConfigTag.PRECISE_MANAGE`）菜单下全部 7 个 Compose 子界面
> 目标：顶栏视觉（背景色/壁纸/不透明度/底部圆角/阴影线/状态栏贯通）与精准管理 `TitleBar` 完全一致

## 根因

精准管理主界面（`TitleBar`/AppBarLayout，`activity_config.xml:8`）走传统 View + `TopBarConfig` 全渲染管线：背景/壁纸/不透明度/底部圆角/`elevation` 阴影/状态栏贯通，见 `TitleBarConfig.applyTopBarConfig()`（`TitleBarConfig.kt:98`，`elevation = context.elevation`）。

7 个 Compose 子界面则全部使用**纯色降级接口** `pageTopBarContainerColor()`（=`colorScheme.secondary`，`CommonPageColors.kt:278`），导致：

1. **阴影缺失**：`TopAppBarDefaults.topAppBarColors()` 无 elevation 参数，7 页全部 0 阴影；`TitleBar` 有 `elevation = context.elevation`（默认 `design_appbar_elevation` ≈4dp，或用户配置 `AppConfig.elevation`）。
2. **宽度/占宽观感不同**：`TitleBar` 是 `match_parent` 全宽 + `fitStatusBar` 贯通状态栏的一条全宽色带（带阴影地平线）；Compose 页是独立 Activity + edge-to-edge，顶栏靠 `WindowInsets.statusBars` 在内部补高度，标题/图标起始 inset 与 Toolbar 的 `contentInsetStartWithNavigation` 不一致，阴影线消失后"横向占宽边界"感知不到。
3. **无圆角/无壁纸/不透明度 100%**：`pageTopBarContainerColor()` 只返回一个纯色。

Compose 侧完整对等实现已存在：`pageTopBarColors()`（内含 `shadowElevation = context.elevation` 计算，`CommonPageColors.kt:57`）+ `Modifier.pageTopBarBackground()`（`.shadow` + 圆角 + 壁纸 + 透明度，`CommonPageColors.kt:117`）——与 `TitleBarConfig` 读**同一个 `TopBarConfig`**，公式一致。`HomepageScreen.kt:201`、`ConfigManageScaffold.kt:49`、`CoverGalleryScreen.kt:104` 已是正确模板。

## 改造内容

### A. 模板组件 `AppPageTopBar`（`ui/widget/components/AppPageTopBar.kt`）

- 内部改用 `val colors = pageTopBarColors()`（替换 `pageTopBarContainerColor()` 与 `colorScheme.onSecondary`）。
- 导航/标题/操作图标颜色统一 `colors.contentColor`（替代三处 `onSecondary`）。
- 新增参数 `showBackground: Boolean = true`：
  - `true`（默认）：`modifier.pageTopBarBackground(colors)`，TopAppBar 容器透明 → 自带背景 + 阴影 + 圆角 + 壁纸。
  - `false`：修饰符原样，完全透明 → 由外层容器承载背景（下载/文件两页的连体场景）。
- `containerColor` 默认值 `pageTopBarContainerColor()` → `Color.Transparent`（背景统一由 `pageTopBarBackground` 承载；现有 4 个调用方中仅 FileManage 显式传过 `Color.Transparent`，语义兼容）。
- 同步更新 KDoc 与 `@Preview`。

### B. 四个核心页面（`AppPageTopBar` 调用方）

- **存储管理 / 书源回收站**：模板默认生效，零代码改动；如留有对 `pageTopBarContainerColor`/`topBarColor` 的引用与 import，一并删除。
- **下载管理**：顶栏 + TabRow 连体渲染：
  ```
  Column(Modifier.pageTopBarBackground(topBarColors)) {
      AppPageTopBar(..., showBackground = false) { actions }
      TabRow(containerColor = Color.Transparent, contentColor = topBarColors.contentColor) { ... }
  }
  ```
  删除局部 `topBarColor`，新增 `pageTopBarColors`/`pageTopBarBackground` import。
- **文件管理**：顶栏 + 搜索栏连体渲染：
  ```
  Column(Modifier.pageTopBarBackground(topBarColors)) {
      AppPageTopBar(..., showBackground = false) { actions }
      AppSearchBar(...)
  }
  ```
  `AppSearchBar` 本身是独立卡片（`pageCardContainerColor`），不透明度需求，不动。删除局部 `topBarColor`，新增相应 import。

> 连体布局即"阴影落在一整块（顶栏 + Tab/搜索）底部"，与 `TitleBar` 内嵌 `tab_layout`/`search_view` 时阴影位于 TitleBar 底部的传统行为一致。

### C. 其余三个页面（就地套用同款模板，不动结构与其他规范项）

每个页面统一做三处替换：

- `pageTopBarContainerColor()` → `val topBarColors = pageTopBarColors()`。
- `TopAppBar` 加 `Modifier.pageTopBarBackground(topBarColors)`。
- `TopAppBarDefaults.topAppBarColors`：`containerColor`/`scrolledContainerColor` → `Color.Transparent`；三处 `colorScheme.onSecondary` → `topBarColors.contentColor`。

涉及位置：

- `UrlRecordScreen.kt` 约 L122-130（注意保留其 `scrollBehavior` 等已有参数）。
- `ModuleStatusScreen.kt` 约 L62-90。
- `PermissionManageScreen.kt` 约 L31-53（顺带消除硬编码 `colorScheme.secondary`）。
