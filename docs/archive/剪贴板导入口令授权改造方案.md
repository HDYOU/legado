# 剪贴板导入口令授权改造方案

## 背景

提交 `439dd0a15 feat: 导入时询问剪贴板访问（每次读取前弹窗确认，设置页可开关）`
引入了「读取剪贴板前弹窗确认」的能力，但落地后打扰过重，用户反馈两个问题：

1. 每次回到主界面都弹窗询问。
2. 没有记忆，每次都要重新选。

## 现状与问题

`MainActivity` 中有两处调用 `readShibboleth()`：

- `onResume()` → `readShibboleth(500)`：从任意子 Activity 返回主界面都会触发。
- `onPostCreate()` → `readShibboleth(1500)`：冷启动时触发。

具体缺陷：

1. **`onResume()` 无差别触发**：应用内 `MainActivity → 设置 → 返回` 也会走询问流程，这是「每次回到主界面都弹窗」的直接原因。
2. **冷启动重复触发（既有 bug）**：生命周期顺序为
   `onCreate → onStart → onPostCreate → onResume`，冷启动时 `onPostCreate` 的
   1500ms 与 `onResume` 的 500ms 两个 `postDelayed` 都会执行，导致同一次进入弹两次窗。
3. **先问后读，无谓打扰**：不管剪贴板里有没有 `#L:` 口令都弹窗。
4. **无记忆**：勾选项只影响当次，下次重新问。

设置项现状：`PreferKey.askClipboardImport`（Boolean，`SwitchPreference`），
开启=每次询问，关闭=彻底不读剪贴板。

## 设计方案

### 1. 触发时机：只在「从外部进入主界面」时检查

在 `LifecycleHelp`（已注册的 `Application.ActivityLifecycleCallbacks`）中维护前后台计数：

- `onActivityStarted`：计数 +1；若 +1 前计数为 0，说明 App 从后台回到前台（或冷启动），
  置 `enteredFromExternal = true`。
- `onActivityStopped`：计数 -1。
- 对外提供消费式读取 `consumeEnteredFromExternal(): Boolean`（读完即清，避免值被复用）。

`MainActivity.onResume()` 仅在返回 `true` 时执行口令检查。

覆盖场景：

| 场景                                | started 计数变化                  | 是否触发                                   |
| ----------------------------------- | --------------------------------- | ------------------------------------------ |
| 冷启动                              | 0 → 1                             | 是                                         |
| 按 Home 切走再切回                  | 1 → 0 → 1                         | 是（去浏览器复制口令后切回，正是核心场景） |
| 外部应用 intent 跳入（后台态）      | 0 → 1                             | 是                                         |
| 应用内 `MainActivity → 设置 → 返回` | 1 → 2（返回时 +1 发生在 -1 之前） | 否                                         |
| 主界面内切 Tab                      | 不变                              | 否                                         |

`MainActivity` 是 `singleTask`，当 App 已在前台时外部 intent 只走 `onNewIntent()`、
不走 `onStart`，因此 `onNewIntent()` 中也要置位。

同时删除 `onPostCreate()` 里的 `readShibboleth(1500)`，统一由 `onResume()` 驱动，
顺带修掉冷启动重复弹窗的 bug。

### 2. 先探测再询问

流程调整为：

```
从外部进入 → 读剪贴板 → 不含 "#L:" → 静默返回
                      → 含口令 → 按 clipboardImportMode 处理
```

这样即便从外部进入，绝大多数情况（剪贴板是别的内容）也不会弹窗。

**取舍**：弹窗语义从「是否允许访问剪贴板」变为「是否导入检测到的口令」。
前台读取剪贴板本身无需权限，探测只在本地判断文本特征，不联网、不落库，
因此在隐私上可接受，而体验收益显著。

### 3. 记忆：三态偏好替代布尔开关

新增 `PreferKey.clipboardImportMode`（String）替换 `askClipboardImport`（Boolean）：

| 值            | 行为                            |
| ------------- | ------------------------------- |
| `ask`（默认） | 从外部进入且剪贴板有口令时询问  |
| `always`      | 直接自动导入，导入时 Toast 提示 |
| `never`       | 从不读取剪贴板                  |

弹窗增加「记住我的选择」勾选框：

- 勾选 + 确定 → 写入 `always`
- 勾选 + 取消 → 写入 `never`
- 未勾选 → 模式不变，仅本次生效

设置页将 `SwitchPreference` 换成 `NameListPreference`（项目内已有同款用法，
如 `updateToVariant`），三选一可见可改，避免「记住了拒绝就再也找不回来」。

旧 key 迁移：`askClipboardImport` 存在且为 `false` → 迁移为 `never`，
其余 → `ask`，随后移除旧 key。一次性执行。

### 4. Toast

仅在 `always` 模式且**真的从剪贴板解析到口令并弹出导入对话框**时提示，
不在每次切回时弹。

## 改动文件清单

| 文件                                                | 改动                                                       |
| --------------------------------------------------- | ---------------------------------------------------------- |
| `constant/PreferKey.kt`                             | 新增 `clipboardImportMode`                                 |
| `help/LifecycleHelp.kt`                             | 前后台计数 + `consumeEnteredFromExternal()`                |
| `ui/main/MainActivity.kt`                           | 触发时机收敛、`onNewIntent()`、三态分支、勾选框弹窗、Toast |
| `res/xml/pref_config_other.xml`                     | `SwitchPreference` → `NameListPreference`                  |
| `res/values/arrays.xml`                             | 三态 entries / entryValues                                 |
| `res/values/strings.xml`（含 zh / zh-rTW / zh-rHK） | 新增与改写文案                                             |
| `help/config/AppConfig.kt` 或 `App.kt`              | 旧 key 一次性迁移                                          |
| `res/layout/`                                       | 新增弹窗勾选框布局                                         |

## 执行步骤

1. `LifecycleHelp` 前后台计数。
2. `PreferKey` 新增常量 + 旧 key 迁移。
3. `MainActivity`：时机收敛、三态分支、勾选框弹窗、Toast。
4. 设置页 `NameListPreference` + arrays + 四语言文案。
5. `./gradlew.bat :app:compileAppMaxDebugKotlin` 语法验证。
